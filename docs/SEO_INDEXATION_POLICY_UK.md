# Політика індексації та SEO-пріоритетів Vonco Partners

Оновлено: 29.07.2026

## 1. Пріоритет мов

1. **Російська (`/ru`)** — основний SEO-напрям для залучення водіїв. На цій версії зосереджені комерційні запити про роботу в таксі у Польщі, Uber, Bolt, Free Now, оренду та викуп автомобіля.
2. **Українська (`/uk`)** — другий пріоритет для цільової аудиторії водіїв.
3. **Польська (URL без мовного префікса)** — важлива корпоративна й локальна версія. Кореневі URL збережено, щоб не створювати масові перенаправлення та не втрачати вже накопичені сигнали.
4. **Англійська (`/en`)** — допоміжна версія для міжнародних користувачів.
5. Інші переклади залишаються доступними, якщо сторінка має повний локалізований контент. Грузинська версія тимчасово виключена із sitemap та має бути перекладена й перевірена перед індексацією.

`x-default` спрямовується на російську версію, якщо вона існує для конкретної сторінки. Canonical кожної індексованої мови залишається самопосилальним.

## 2. Сторінки першої черги

- `/ru`
- `/ru/work`
- `/ru/cars`
- `/ru/services`
- `/ru/cities`
- `/ru/vykup-avto`
- `/ru/documents-for-taxi-work`
- `/ru/blog`
- російські сторінки Катовице, Кракова, Гданська та відповідних платформ;
- російські статті про старт роботи, оренду авто, викуп і роботу в Катовице.

Для цих URL обов’язково перевіряються:

- унікальні title, description та один H1;
- self-canonical;
- російський `x-default`;
- відсутність `noindex`;
- релевантна внутрішня перелінковка;
- коректний JSON-LD;
- наявність у sitemap;
- відсутність випадкового тексту іншою мовою.

## 3. Що не слід масово індексувати

Не можна автоматично ставити `noindex` на всі сторінки з низьким трафіком. Низький трафік сам по собі не означає низької якості.

Кандидати на виключення визначаються лише після експорту конкретних URL з Google Search Console:

- технічні дублікати;
- застарілі URL без самостійної цінності;
- сторінки з помилковою або неповною локалізацією;
- сторінки, зміст яких повністю дублює іншу canonical-сторінку;
- URL, створені параметрами або помилковою навігацією.

Redirect URL, свідомий `noindex` і видалені сторінки не потрібно повертати в sitemap. Для 404 спочатку перевіряється наявність внутрішніх посилань; якщо є релевантна заміна, налаштовується постійне перенаправлення.

## 4. Дані, потрібні для точного очищення

Із Google Search Console потрібно експортувати таблиці URL для причин:

- `Crawled - currently not indexed`;
- `Duplicate, Google chose different canonical than user`;
- `Not found (404)`;
- `Page with redirect`;
- `Excluded by noindex tag`.

Без цього експорту можна перевірити технічну політику сайту, але не можна безпечно вирішити долю кожного з 90 сторінок у статусі `Crawled - currently not indexed`.

## 5. Контроль після публікації

1. Запустити `npm run seo:priority https://vonco.partners`.
2. Запустити повний `npm run site:audit -- https://vonco.partners`.
3. Повторно подати sitemap у Search Console.
4. Запросити індексацію пріоритетних російських URL через URL Inspection.
5. Щотижня контролювати impressions, clicks, CTR, average position і кількість заявок для `/ru`.
6. Через 4–6 тижнів порівняти запити та сторінки з базовим періодом; загальні SEO-інструменти не замінюють дані Search Console.

## 6. Контентний розвиток

Наступні сторінки мають створюватися за реальними питаннями водіїв і підтвердженими джерелами. Юридичні, податкові та міграційні матеріали публікуються лише після перевірки відповідним фахівцем. Дати перевірки, авторство компанії та офіційні джерела потрібно показувати безпосередньо на сторінці.
